# SSH 路由账号、文件面板和密码

## 带斜杠的 SSH 用户名

部分 SSH 网关用带斜杠的路由用户名选择目标主机和账号，例如
`alice/192.0.2.10/root`。将完整用户名填到独立的“用户名”字段，
“主机地址”和端口填写管理员提供的 SSH 网关入口。

原生和 Electron 版本支持这种分段用户名；终端、SFTP 与共享连接均通过
独立的 `-o User=…` 参数传给 OpenSSH，避免 SFTP 将斜杠解析为路径。

这种路由是否可用，以及是否允许 SFTP 或额外的非交互命令通道，取决于 SSH 服务器配置。
交互终端能登录不代表文件面板和主机监控一定获得了相同授权。
普通 ProxyJump 仍要求 SSH 网关支持 TCP 转发。

## 首次固定密码与动态验证码

原生版编辑 SSH 连接，勾选“记住首次登录密码（系统钥匙串）”，保存并重新连接。
首次密码在独立的 SSH 认证窗口输入；勾选保存后写入系统钥匙串。
再次连接相同目标、账号、端口和认证提示时，首次固定密码会自动填写。
`2nd Password`、动态验证码、密钥口令和后续重试提示始终需要手动输入，不保存。

密码不会写进 profiles.json、终端输入或历史、命令行参数及环境变量。
native-profile-ssh-auth.json 只保存哪些连接启用此功能的布尔值。
SSH 密码和模型 API Key 使用不同的钥匙串服务。
钥匙串不可用时明确提示，可取消勾选保存后仅用于本次登录，不降级为明文存储。
编辑页的“忘记已保存的首次密码”会删除该连接的凭据；关闭记住选项仅停止自动填写。
主机指纹仍需用户确认，不自动信任未知主机。

## 通道拒绝的提示

文件与监控分别报告认证失败、主机指纹失败、服务器拒绝新增会话通道或不支持 SFTP。
共享登录的伴随通道失败后不会自动回退到新登录，避免意外重复触发多因素认证。
可以在设置中关闭“SSH 文件面板与主机监控”，再创建只使用交互终端的连接。

## 验证与平台范围

Linux 的 scripts/test-ssh-password.py 使用私有 D-Bus、临时系统钥匙串、Xvfb、
虚构凭据及回环 SSH 服务，验证两次真实 OpenSSH keyboard-interactive 登录：
首次手动输入固定密码和验证码，第二次仅输入新验证码，并检查没有保存验证码。
设置 OMNITERM_SSH_TEST_ROUTED=1 可用带斜杠的路由用户名执行同一测试。

本地 Linux 测试不代表 macOS 或 Windows 已完成真实窗口、系统钥匙串及远端接入验收。
三平台构建和 lint 由 CI 分别执行；下载测试包时应核对对应提交和平台。
