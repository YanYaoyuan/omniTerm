# SSH 路由账号、文件面板和密码

## 带斜杠的 SSH 用户名

部分 SSH 网关用带斜杠的路由用户名选择目标主机和账号，例如
`alice/192.0.2.10/root`。将完整用户名填到独立的“用户名”字段，
“主机地址”和端口填写管理员提供的 SSH 网关入口。

原生和 Electron 版本支持这种分段用户名；终端、SFTP 与共享连接均通过
独立的 `-o User=…` 参数传给 OpenSSH，避免 SFTP 将斜杠解析为路径。

这种路由是否可用，以及是否允许 SFTP 或额外的非交互命令通道，取决于 SSH 服务器配置。
交互终端能登录不代表文件面板和主机监控一定获得了相同授权。
普通 ProxyJump 仍要求 SSH 网关支持 TCP 转发。

## 首次固定密码与动态验证码

原生版编辑 SSH 连接，勾选“记住首次登录密码（系统钥匙串）”，保存并重新连接。
首次密码在独立的 SSH 认证窗口输入；勾选保存后写入系统钥匙串。
再次连接相同目标、账号、端口和认证提示时，首次固定密码会自动填写。
`2nd Password`、动态验证码、密钥口令和后续重试提示始终需要手动输入，不保存。

密码不会写进 profiles.json、终端输入或历史、命令行参数及环境变量。
native-profile-ssh-auth.json 只保存哪些连接启用此功能的布尔值。
SSH 密码和模型 API Key 使用不同的钥匙串服务。
钥匙串不可用时明确提示，可取消勾选保存后仅用于本次登录，不降级为明文存储。
编辑页的“忘记已保存的首次密码”会删除该连接的凭据；关闭记住选项仅停止自动填写。
主机指纹仍需用户确认，不自动信任未知主机。

## 通道拒绝的提示

文件与监控分别报告认证失败、主机指纹失败、服务器拒绝新增会话通道或不支持 SFTP。
共享登录的伴随通道失败后不会自动回退到新登录，避免意外重复触发多因素认证。
可以在设置中关闭“SSH 文件面板与主机监控”，再创建只使用交互终端的连接。

## 齐治 AccessClient 文件连接

原生版可将 AccessClient 导出的 WinSCP 连接参数绑定到一个 SSH 资产。通过连接编辑页
或当前 SSH 的文件区域导入参数文件，核对绑定的资产、文件入口及会话标题后确认。
之后仍使用原有的“文件”面板：目录浏览、上传下载、进度、取消和覆盖确认不变，
切换终端标签时切换各自的目录。不需要选择新的连接模式。

后台只对这条绑定连接启用齐治适配器。终端继续原有交互登录，文件通道使用导出参数
中的独立 SFTP 入口和账号，不复用终端的 control socket，也不在文件通道运行主机监控。
普通 SSH/SFTP、其他堡垒机、SSH config 与 ProxyJump 的默认行为不变。
为避免齐治登录期间被额外的共享会话打断，具有文件参数绑定的 SSH 连接不启用共享伴随通道。

参数文件必须是已解包的 AccessClient JSON，或诊断接收器保存的 `parameters` 对象包装。
适配器读取小写 `pwd`；大写 `PWD` 不作为替代密码。`st` 仅作为会话标题，不作为令牌使用。
不执行导出文件中的安装包 URL、外部客户端路径或命令。出现冲突的大小写入口字段、
不支持的代理参数、非 SFTP 协议或无效地址时会拒绝连接。

参数绑定保存在原生版单独的配置文件中，只包含源文件路径、文件入口信息和确认时的 SSH 目标；
不向共享的 `profiles.json` 添加字段。不会把捕获的密码自动保存到系统钥匙串。
每次认证只自动提交一次本次导入的凭据；额外验证码通过独立认证窗口手动输入，不保存。
用于 askpass 的临时凭据文件在私有目录中创建，首次读取后删除，关闭连接时清理认证状态。
导出 JSON 本身可能包含临时凭据，应保留在本机受控位置，不加入仓库或公开问题报告。

断线后由用户重连文件通道，不影响终端。参数过期时重新获取并导入；重新读取参数发现
入口、账号或资产标题改变时，必须重新确认绑定，不能静默切换到另一台资产。
目前不会向堡垒机自动续取文件连接凭据。若导出凭据无法完成认证，应在堡垒机重新打开
该资产的文件连接；新参数覆盖原文件且目标不变时，点击文件面板的重连即可重新读取，
使用新文件路径时则重新导入。终端已保存的登录密码不一定能替代文件入口的导出凭据。
再次出现密码提示不直接等同于过期：服务端也可能要求额外认证，验证码仍可手动输入。
如果 Electron 或外部编辑修改了共享配置中同一连接 ID 的 SSH 目标，旧文件绑定会停用，
需要重新导入确认；不能将原资产的文件目录挂到修改后的终端。
本功能不注册 `accessclient://` 协议，也不自动启动浏览器或第三方客户端。

## 验证与平台范围

Linux 的 scripts/test-ssh-password.py 使用私有 D-Bus、临时系统钥匙串、Xvfb、
虚构凭据及回环 SSH 服务，验证两次真实 OpenSSH keyboard-interactive 登录：
首次手动输入固定密码和验证码，第二次仅输入新验证码，并检查没有保存验证码。
设置 OMNITERM_SSH_TEST_ROUTED=1 可用带斜杠的路由用户名执行同一测试。

本地 Linux 测试不代表 macOS 或 Windows 已完成真实窗口、系统钥匙串及远端接入验收。
三平台构建和 lint 由 CI 分别执行；下载测试包时应核对对应提交和平台。

本机并行验收新版本时，可将 `OMNITERM_DATA_DIR` 设置为独立的绝对目录，避免覆盖正在使用的
应用配置与工作区。它只改变 omniTerm 的数据目录，不改变 OpenSSH 的 known_hosts 或系统钥匙串。

可使用构建后的原生程序进行只读连接诊断，参数中只传本地导出文件路径：

```sh
omniterm-app --verify-file-connection /path/to/accessclient-connection-parameters.json
```

诊断复用文件面板的连接、认证和目录读取实现，只输出是否成功、目录及条目数，不打印凭据或
服务器原始错误文本。它不会传输文件、执行远端命令、启动监控或自动重试，并在结束时关闭自己的连接。
