# omniTerm 路线图

omniTerm 面向 macOS、Linux 和 Windows，将终端、远程连接与 Agent 放在同一个工作区。
当前发布版本为 [0.0.1](https://github.com/YanYaoyuan/omniTerm/releases/tag/v0.0.1)。

**下一阶段最高优先级：让 omniTerm Agent 感知工作区、获取指定终端上下文并明确操作目标。**
同时统一产品名称，并接入用户自己的 Qwen、Claude、Kimi、OpenRouter 等 API。
具体交互、架构、开发顺序与验收门槛见 [Agent 工作区开发方案](agent-workspace-plan.md)。

## 0.0.1 基线

| 能力 | 已有实现 | 后续重点 |
| --- | --- | --- |
| 本地终端 | Electron/React、xterm.js、node-pty、标签、嵌套分屏、广播、搜索、命令面板、13 套主题 | 输入法、性能、可访问性和快捷键配置 |
| 工作区 | 本地标签、分屏比例、名称与目录恢复为新 shell | 生命周期一致性；命令不重放，远程会话不自动重连 |
| Agent | 独立 PTY 中运行上游 TUI，支持粘贴选中的终端文本 | 感知终端清单、自动获取选定上下文、固定执行目标、结构化面板 |
| SSH | 保存配置、SSH config 导入、ProxyJump 跳板配置、系统 OpenSSH | 导入边界修复、连接状态、重连和任务目标一致性 |
| SFTP 与指标 | 图形文件浏览、文件/目录传输、传输队列、取消与确认、远端主机指标 | 交互完善、平台与服务器差异回归 |
| 转发与串口 | 本地/远程/动态 SSH 转发，pyserial 串口会话 | 独立转发管理、设备发现、收发视图及日志 |
| 发行 | macOS arm64 ZIP、Ubuntu 22.04 amd64 deb、Windows x64 ZIP，校验值与来源清单 | 发行者签名、公证、更多安装器/架构、升级流程 |

0.0.1 已完成三平台代码 CI 和相应原生运行检查。macOS 有窗口观察，Ubuntu 有普通用户安装及
隔离 Xvfb/PTY 验证，Windows 有真实 Electron/ConPTY 自动化验证；Windows 人工 GUI、
所有模型任务与硬件场景并未因此全部覆盖。具体以 Release 说明和验收记录为准。

## 下一阶段：Agent 工作区

| 优先级 | 交付目标 | 完成标准 |
| --- | --- | --- |
| P0：上下文与目标 | 知道打开的标签/分屏；读取一个或多个选定终端；操作目标独立固定 | 能分析 A+B，只操作 B；切焦点、广播、关闭或重连都不串线 |
| 同步：产品名称 | 默认产品界面统一为 omniTerm Agent，接入结构化消息/工具/审批界面 | 产品流程不再展示旧 Agent 品牌；内部兼容标识与法务署名保留 |
| P1：多模型 | OpenAI 可选，支持 Qwen、Claude、Kimi、OpenRouter 和自定义协议配置 | 每家至少一个真实端点/模型完成流式与连续工具回环，使用同一套终端执行约束 |

实现顺序：接口与权限验证 → 工作区目录和上下文 → 明确目标执行 → 多模型与跨平台验收。
模型协议工作可以并行推进，但不能绕过终端目标和授权层。
新增能力在 [开发方案](agent-workspace-plan.md#8-必须通过的验收场景) 中逐项验收后再标为已支持。

## 后续持续改进

- 完善命令边界、长输出、Unicode、输入法、休眠/恢复及多会话资源使用。
- 修复复杂 SSH config 导入、设置反馈、背景图校验和运行中 TUI 主题切换等已知边界。
- 加强文件传输、重连、主机密钥变化、认证失败及连接退出的真实环境回归。
- 增加串口设备能力和转发管理；它们采用各自的操作语义，不默认当作 shell。
- 建立签名、安装器、升级和配置迁移流程，并持续记录实际覆盖的平台与模型组合。
- 先保持当前桌面架构；后续根据性能和维护数据评估 Rust 核心扩展，另行决定是否迁移原生界面。
