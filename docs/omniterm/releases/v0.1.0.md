# omniTerm 0.1.0

This release adds a terminal-aware Agent, configurable workspace panels, and process monitoring to omniTerm's local and remote terminal workspace.

## Highlights

- A Rust terminal host keeps PTY sessions and terminal state outside the renderer.
- The Agent uses explicitly selected context and execution targets, with command proposals, approval, cancellation and target withdrawal. It supports existing OpenAI login and configurable model services.
- Optional SSH approved execution checks shell readiness before submission. SSH auto-submit is off by default; staged commands still require manual Enter. Interactive-program input uses a separate approved operation.
- Drag and dock the Agent, workspace, terminal and monitoring panels. Moving a panel preserves running sessions and in-memory conversations, approvals and monitoring. Saved layouts reopen with fresh shells.
- Monitor supported processes, threads and logs, with history and approved actions. A separate process window provides a process overview. Windows supports process, thread and log monitoring; shared-memory monitoring is unavailable there.
- Window chrome follows the selected light/dark theme, including Windows and Linux title controls. Model settings save and close correctly, and errors provide clearer recovery guidance.

Extract the entire Windows ZIP before starting `omniTerm.exe`. Each package has a SHA-256 checksum and source/build manifest; `SHA256SUMS` covers the complete asset set. No personal login, API keys, SSH configuration or application data is included. Model access requires your own account or provider configuration; model weights are not bundled.

These are unsigned early-release packages: Windows has no Authenticode certificate, and macOS is ad-hoc signed without Developer ID or notarization. Native build and packaged-runtime checks run separately on each target platform; check the release workflow for the final artifact results.

## Acceptance and limits

The accepted source tree passed 112 Rust terminal-host tests, 193 JavaScript tests (14 skipped), the real Windows ConPTY and packaged-runtime checks, and four real-model checks using existing OpenAI login. Targeted regressions covered monitor lifecycle races, real Windows threads, and replacement log identity. The maintainer also accepted panel moves with conversations, pending approvals and monitoring, plus transparent-mode window controls after restart. Release metadata and packaging changes are validated separately by the release workflow.

- Real remote SSH, nested SSH/tmux/su, monitoring over SSH, other model services and complete macOS/Linux manual acceptance remain outside this acceptance record. [Issue #4](https://github.com/YanYaoyuan/omniTerm/issues/4) stays open.
- Monitoring runs while the application is open. Moving a panel preserves its state; restarting the application does not restore running shell processes or monitor tasks.
- Unsupported shell states or readiness-check failures leave commands staged or blocked. Only operations reported as staged need manual submission; approved execution and staging have distinct status labels.
- A terminal pane cannot yet be dropped onto the terminal area's own edge.
- An in-place log rewrite changing only the middle, or a POSIX replacement reusing an inode with matching sampled content, may not be detected. Rotation during a sample can repeat text.

Please report regressions with the platform, release version and relevant error details, omitting credentials.
