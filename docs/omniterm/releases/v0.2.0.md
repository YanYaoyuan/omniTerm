# omniTerm 0.2.0 — Native Preview

This release introduces the Rust native application alongside the existing Electron application. The native app renders terminal cells directly through wgpu, with an egui interface and the shared Rust terminal backend. It does not need Electron or a browser runtime.

This is a prerelease. Download native packages and the independent agent Skill from [v0.2.0 assets](https://github.com/YanYaoyuan/omniTerm/releases/tag/v0.2.0). The external CLI requires Node.js 22+ on the same operating system as omniTerm.

## Highlights

- External terminal CLI: discover connected assets, bind a specific instance/session, prepare supported shell integration, execute commands, check exit codes and read incremental or searched output. Unknown outcomes are queried using the original request ID.
- External SFTP CLI: bind an existing SSH file panel or standalone SFTP window, browse/stat files, create/rename/remove paths, upload/download recursively when requested, track progress and cancel transfers. Existing authentication is reused; overwrite is refused by default.
- Standalone `omniterm-control` Skill for Codex and Claude Code. The entry stays concise; terminal, SFTP and recovery references load as needed. Its launcher locates the CLI in installed native packages, including a separately copied Skill.
- Web-authorized SSH/SFTP windows for the documented direct `accessclient://` format, plus ten content-highlighting choices with persistent settings and live previews.

- Native terminal workspace with tabs, split panes, search, selection, clipboard, workspace restoration, themes, monitoring and the omniTerm Agent interface.
- Custom local Shell executable and argument list for new terminals, splits and workspace restoration. Late split completions are reclaimed when their target has closed or moved.
- Docked panel sizes remain stable after resizing. Monitor forms, long Agent labels and process names stay within their panels.
- SSH X11 forwarding with off, restricted (`-X`) and trusted (`-Y`) modes. Linux uses the current display; macOS uses XQuartz; Windows integrates with an installed VcXsrv or Xming server. Interactive SSH sessions forward X11 independently of their SFTP and metrics channels.
- SFTP file drag-out on Linux X11 and Wayland, with native platform integration on Windows and macOS. The first drag downloads the item; drag again when it is marked ready to hand it to a local file manager.
- Clear SFTP upload/download bars, percentages and byte counts. Active transfers appear above history; completed transfers retain their full bars.
- Queued transfers cancel immediately. Canceled drag downloads do not remain stuck preparing. Interrupted uploads preserve the destination and track temporary files for cleanup when that connection is retried.
- Closing an SSH tab does not block the interface while waiting for its SFTP process. Canceled transfers have a bounded cleanup period; application shutdown joins that cleanup.

| Windows x64 | `omniTerm-native-0.2.0-windows-x64.zip` |
| macOS Apple Silicon | `omniTerm-native-0.2.0-macos-arm64.zip` |
| Ubuntu 22.04 amd64 | `omniterm-native_0.2.0-1_amd64.deb` |
| Linux x64 portable | `omniTerm-native-0.2.0-linux-x64.tar.gz` |

Each native package has a `.sha256` checksum and `.manifest.json` build record. Normal CI artifacts ending in `-app-only` omit the Agent; they are separate from the full release packages. The release workflow also builds the Electron packages under their existing names at version 0.2.0.

Extract the complete Windows ZIP before starting the app. SSH/SFTP requires system OpenSSH; remote graphical apps also require a local X server. Model access requires an account or provider configuration; model weights are not bundled.

## Install the agent Skill

Download `omniterm-control-skill-0.2.0.zip` and its `.sha256` sidecar from this release. Extract the archive and copy the complete `omniterm-control/` directory to the agent's skills directory. Keep `scripts/` and `references/` beside `SKILL.md`; the ZIP also includes Apache-2.0 licensing and notices.

- Codex: `~/.codex/skills/omniterm-control/` (or `$CODEX_HOME/skills/omniterm-control/` when customized).
- Claude Code: `~/.claude/skills/omniterm-control/`.

Restart the coding agent to load the Skill. Install and open the native omniTerm package, connect the intended terminal or SFTP page, then ask the agent to use `omniterm-control`. Verify CLI discovery with `node <skill-directory>/scripts/omniterm.mjs --locate`. If automatic location fails, set `OMNITERM_CLI_ENTRY` to the installed `omniterm-cli/bin/omniterm.js`. Full instructions: [Skill installation](../../../omniterm-cli/skills/README.md).

## Known limits

- The external CLI controls existing native windows; Electron does not expose this channel. Login/MFA and opening connections remain in the desktop UI. Results and request deduplication live in the app process and do not survive restart. Terminal output is bounded merged PTY text, with truncation reported.
- Hosted checks cover all three operating systems. Real terminal/SFTP window automation was accepted on isolated Linux services; company assets and full macOS/Windows manual CLI acceptance remain outside that record. Web-authorized assets support only the documented direct format, without additional proxy parameters.

- Windows, macOS and Wayland X11/drag-out paths have not been manually accepted. Wayland has no equivalent coverage in the current CI. The Linux test results above do not establish cross-platform manual acceptance.
- Real model tasks, monitoring in real workloads, terminal-pane docking and shell-readiness integration still need native-app acceptance. Existing Electron acceptance records do not establish acceptance for the new interface.
- A running transfer can clean remote temporary files only while the server is reachable. Upload temporary paths are retained for cleanup on retry within the same SSH session; cleanup is not a promise to recover every file after an application crash or an unreachable server.
- Nautilus rejects drops over its empty-folder placeholder icon; drop into the file-list blank area.
- Packages have no publisher certificate or automatic updates. macOS uses an ad-hoc signature, with no Developer ID or notarization.
- Workspace restoration starts new shells; it does not restore running processes.

Please report regressions with the platform, display system, version and relevant error details, omitting credentials.
