# omniTerm 0.2.0 — Native Preview

This release introduces the Rust native application alongside the existing Electron application. The native app renders terminal cells directly through wgpu, with an egui interface and the shared Rust terminal backend. It does not need Electron or a browser runtime.

Release preparation: use tag `v0.2.0` and mark the GitHub release as a prerelease. Publish download links after the complete release build and artifact validation finish.

## Highlights

- Native terminal workspace with tabs, split panes, search, selection, clipboard, workspace restoration, themes, monitoring and the omniTerm Agent interface.
- Custom local Shell executable and argument list for new terminals, splits and workspace restoration. Late split completions are reclaimed when their target has closed or moved.
- Docked panel sizes remain stable after resizing. Monitor forms, long Agent labels and process names stay within their panels.
- SSH X11 forwarding with off, restricted (`-X`) and trusted (`-Y`) modes. Linux uses the current display; macOS uses XQuartz; Windows integrates with an installed VcXsrv or Xming server. Interactive SSH sessions forward X11 independently of their SFTP and metrics channels.
- SFTP file drag-out on Linux X11 and Wayland, with native platform integration on Windows and macOS. The first drag downloads the item; drag again when it is marked ready to hand it to a local file manager.
- Clear SFTP upload/download bars, percentages and byte counts. Active transfers appear above history; completed transfers retain their full bars.
- Queued transfers cancel immediately. Canceled drag downloads do not remain stuck preparing. Interrupted uploads preserve the destination and track temporary files for cleanup when that connection is retried.
- Closing an SSH tab does not block the interface while waiting for its SFTP process. Canceled transfers have a bounded cleanup period; application shutdown joins that cleanup.

## Validation

The accepted functional commit [`98c01cac9`](https://github.com/YanYaoyuan/omniTerm/commit/98c01cac91143a71b16e62daeb923dddba2edf5e) passed [all 17 CI checks](https://github.com/YanYaoyuan/omniTerm/actions/runs/41961850102). Version and release preparation changes have their own subsequent checks.

- Linux native unit tests: 96 passed. The eight SFTP integration tests and one X11 integration test are intentionally excluded from the normal unit-test command and run in dedicated CI steps.
- Real, rate-limited loopback SSH/SFTP: all eight integration tests ran and passed, with no skipped cases. They cover batch and nested-directory round trips, empty files/directories, Unicode and special filenames, running/queued cancellation, mid-transfer disconnection and retry, failures followed by successful work, and SSH tab/application shutdown. Contents are compared byte for byte; temporary-file cleanup and preservation of existing destinations are checked.
- Overwrite confirmation: a UI regression verifies that declining a download replacement leaves the existing file unchanged and queues no transfer.
- X11 forwarding: both restricted and trusted modes executed through real loopback SSH in Linux CI; a remote `xdpyinfo` connected to the forwarded display in each mode.
- Maintainer Linux desktop checks: restricted forwarding opened `xclock`; three SFTP drops to Nautilus preserved filenames and file hashes. Rate-limited 8 MiB uploads/downloads advanced their visible bars, and the uploaded file hash matched.
- CI also builds, lints and packages the application on Windows and macOS. Real-window smoke tests run on Linux and Windows; macOS CI does not open a window.

## Known limits

- Windows, macOS and Wayland X11/drag-out paths have not been manually accepted. Wayland has no equivalent coverage in the current CI. The Linux test results above do not establish cross-platform manual acceptance.
- Real model tasks, monitoring in real workloads, terminal-pane docking and shell-readiness integration still need native-app acceptance. Existing Electron acceptance records do not establish acceptance for the new interface.
- A running transfer can clean remote temporary files only while the server is reachable. Upload temporary paths are retained for cleanup on retry within the same SSH session; cleanup is not a promise to recover every file after an application crash or an unreachable server.
- Nautilus rejects drops over its empty-folder placeholder icon; drop into the file-list blank area.
- Packages have no publisher certificate or automatic updates. macOS uses an ad-hoc signature, with no Developer ID or notarization.
- Workspace restoration starts new shells; it does not restore running processes.

Please report regressions with the platform, display system, version and relevant error details, omitting credentials.
